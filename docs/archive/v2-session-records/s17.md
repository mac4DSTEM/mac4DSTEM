# v2 S17 — sidebar intermittent

**Date:** 2026-08-27  
**Gate:** D  
**Scope:** Identify the run-to-run variable behind
`SidebarLayoutTests.testEveryWorkspaceSidebarFitsItsColumn`, then either put
the threshold on a defensible invariant or quarantine it honestly.

## Outcome

The intermittent was not random layout timing, display scale, the OS, disk
pressure, or the checkout. The test inherited a real user preference:
`ContentView` stores `sidebar.displaySection.expanded` with `@AppStorage`, and
the test never controlled it. The owner driving the app could therefore change
what a later hosted test measured. Forcing the disclosure expanded reproduced
the historical failure triplet exactly; forcing the default-collapsed state
removed every failure except uncalibrated Prepare's independent 62pt miss
against an old 60pt allowance.

The automated claim is now deliberately narrow and reproducible:

- every **default-collapsed**, calibrated workspace fits its sidebar column;
- every default-collapsed, uncalibrated workspace except Prepare fits;
- uncalibrated Prepare is one explicit dynamic `XCTSkip`, with its geometry,
  display scale, screen and WindowServer state attached to every run;
- an intentionally expanded Display disclosure is measured, not gated; Track B
  owns whether that remembered state remains usable on screen.

No threshold was widened. No app code changed.

## Gate D preregistration and refutation

### First diagnosis — refuted

1. **Diagnosis believed:** fixed sleeps were sampling a not-yet-settled
   SwiftUI/AppKit layout.
2. **Refuting observation:** fresh processes settle to the same coherent
   geometry and the isolated gate fails on the same case.
3. **Prediction:** early heights would move while final geometry stayed fixed;
   a settle-to-fixed-point probe would remove the flip.

**Experiment:** three fresh measurement processes were byte-identical:
calibrated workspaces 871/871; uncalibrated Prepare 933/871; every other
uncalibrated workspace 871/871. The isolated gate failed. Timing was refuted
before a fix landed.

### Second diagnosis — incomplete, refuted by the separate reviewer

1. **Diagnosis believed:** the 60pt allowance was the whole defect—an observed
   number rather than a product invariant.
2. **Refuting observation:** a separate uncontrolled state maps the older
   multi-workspace height triplet.
3. **Prediction:** inspection would find no UI row-height constant backing 60.

Inspection confirmed there is no such invariant, but the separate Gate D
reviewer found the stronger refuter in primary code:
`@AppStorage("sidebar.displaySection.expanded")`. Fresh processes had all
inherited/defaulted to the same collapsed value, so the three-run experiment
had not discriminated persisted state.

### Surviving diagnosis

The discriminator ran the same real `ContentView` under private
`defaultAppStorage` stores in separate test entry points. Sidebar width was
292pt; available height 871pt; backing scale 1.0; screen 2560×1440; the window
was visible and occlusion-visible; the session was on-console and login-done.

| calibration | Display | Prepare | Image | Map | Reconstruct | Results |
|---|---:|---:|---:|---:|---:|---:|
| ready | collapsed | 871 | 871 | 871 | 871 | 871 |
| blocked | collapsed | **933** | 871 | 871 | 871 | 871 |
| ready | expanded | **945** | 871 | **961** | 871 | 871 |
| blocked | expanded | **1029** | 871 | 929 | 871 | 871 |

The old failure reported 1029/945/961 and not 929: the first three exceeded
their old allowances; 929 stayed under 871+60. This exact reproduction
confirmed the persisted disclosure as the intermittent axis.

The collapsed Prepare miss remains independent. The all-workspace test's
comment documented 49pt when added; the unchanged UI now measures 62pt. The
60pt constant already existed in the earlier Reconstruct-only test, so the
record does **not** claim that 49 was literally rounded to 60. What the evidence
does establish is that 60 is not a stable product property. That one case is
formally quarantined rather than widened to the latest observation.

## What shipped

- `SidebarLayoutTests`
  - injects a per-test private `UserDefaults` suite through SwiftUI
    `defaultAppStorage`, default-collapsed, so owner preferences and parallel
    test processes cannot affect the gate;
  - replaces the overbroad test with
    `testEveryNonQuarantinedWorkspaceSidebarFitsItsColumn`;
  - keeps uncalibrated Prepare as the separate
    `testUncalibratedPrepareSidebarHeightHasNoNumericGate` skip;
  - attaches `sidebar-s17-geometry.txt` with document/column height, width,
    disclosure state, display scale, screen frame and WindowServer flags.
- `SidebarDensityMeasurementTests`
  - uses the same private AppStorage isolation;
  - records both collapsed and expanded geometry as separate measurements,
    including display and WindowServer state.
- `tools/run-tests.sh`
  - accepts optional `MAC4DSTEM_XCRESULT_BUNDLE_PATH`; local behaviour is
    unchanged when it is absent.
- `.github/workflows/ci.yml`
  - retains the unit xcresult and prints the S17 attachment on every run;
  - states the narrowed default-collapsed claim and the explicit skip.
- `docs/visual-acceptance-checklist.md`
  - splits the old generic sidebar row into default-collapsed uncalibrated
    Prepare and intentionally expanded Display rows.

## Negative control

Before trusting the rewritten gate, its exclusion was deliberately changed
from uncalibrated Prepare to uncalibrated Results. The targeted test failed
(exit 65) when the 933/871 Prepare case re-entered the covered set. The correct
exclusion was then restored and the targeted set passed with one explicit skip.

The first attachment implementation also caught its own cross-process flaw:
the layout and measurement suites briefly shared `UserDefaults.standard`, so
an expanded measurement could race the collapsed gate. A parallel targeted run
reported collapsed geometry but `displayExpanded=true`. Replacing the shared
domain with per-test private AppStorage stores made the same parallel run report
the intended false/true states independently.

## Gate D review

A separate agent reviewed the diagnosis against the observation log, UI source
and experiment output—not the diff. It first **REFUTED** the threshold-only
diagnosis by finding the persisted disclosure. After the controlled experiment
reproduced 1029/945/961 exactly, the same reviewer **CONFIRMED** the surviving
diagnosis and the narrowed fix, with the wording constraint that automation
always says **default-collapsed**.

## Verification
