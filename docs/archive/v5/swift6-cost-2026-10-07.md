# What Swift 6 strict concurrency would cost — measured 2026-10-07

Measurement only; no code changed. Source: `HEAD` 4cc5581c, built from `git archive` scratch copies (folder `mac4DSTEM`, `References` symlinked) on the scratch tree of the 2026-10-07 session, Debug, `-jobs 2`/`-j 2`, `CODE_SIGNING_ALLOWED=NO`. Build logs are named below by their scratch file name (`<variant>-<pkg|app>.out`, run 2026-10-07 22:31–23:23); session logs are gitignored, so every distinct diagnostic is listed by file:line in §4.

## 1. Result in five lines

- Today (Swift 5 mode): **17** distinct warnings (`base-app.out`; 13 concurrency-flavoured, 4 not). The package alone, `base-pkg.out`: 7 (Core 4, Session 3, Training 0).
- Swift 5 + complete checking (`strict-app.out`, `strict-pkg.out`): **59** distinct warnings — Core 43, Session 5, Training 0, app 11. Union with the four app diagnostics that only `base-app.out` emitted: **64 distinct** (60 concurrency, 4 unrelated).
- Swift 6 language mode: the compiler stops early, so the error counts are a first wave only — Core 2, Session 1, Training **0**, app 2 (§3). The 64 above is the better size of the work.
- Metal, `SpectrumImageSource` and HDF5 handles are **not** among the diagnostics (§4). The work is progress counters, MainActor-default helper types in parallel loops, and a handful of statics.
- Estimate: **3.5–5 sessions** (§6). Unmeasured: the `mac4DSTEMTests` target and the `tools/` packages.

Findings that corrected the brief's hypothesis list:

- **Metal:** `MTLDevice` and `MTLCommandQueue` are declared `NS_SWIFT_SENDABLE` in the SDK headers (`MTLDevice.h:460`, `MTLCommandQueue.h:20`, grep of the macOS SDK on 2026-10-07); `MTLBuffer`/`MTLTexture` are not. Neither buffers nor textures cross an isolation boundary in a flagged way: the code has 31 `MTLBuffer` lines in 10 files and 10 `MTLTexture` lines in 2 files and produced **0** diagnostics. The only Metal diagnostic is the singleton itself (`MetalEngine.shared`).
- **`SpectrumImageSource`** (20 lines, 5 files) and **HDF5** (177 `hid_t` lines, 4 files): 0 diagnostics.
- Existing hardening is why the count is small: 33 `@unchecked Sendable` (22 files), 187 `: Sendable` (82 files), 76 `@Sendable` (35 files), 3 `nonisolated(unsafe)`, default MainActor isolation, `InferSendableFromCaptures` already on. 46 `Task.detached` and 12 `concurrentPerform` (9 files) did not all warn.

## 5. Apple's documented remedy per cause

Looked up with the Apple documentation MCP (`search_apple_docs`, 2026-10-07). Where it returned nothing, the gap is stated — not filled from memory.

| Cause | Document (path as returned) | Remedy it documents |
|---|---|---|
| A | "Sendable", `documentation/Swift/sendable`; "Adopting strict concurrency in Swift 6 apps", `documentation/Swift/adoptingswift6` | `@Sendable` closures capture by value; copy to a `let`, or move the state behind a Sendable type. "Mutex" (`documentation/Synchronization/mutex`, macOS 15+): `Mutex<Value>` is Sendable, mutate via `withLock`. |
| B | "Sendable"; "Updating an app to use strict concurrency", `documentation/Swift/updating-an-app-to-use-strict-concurrency` | Make the type a value type/actor/immutable final class; otherwise protect it and mark `@unchecked Sendable`, which the document says you must verify yourself. The `sending` keyword: **no Apple page found**. |
| C | "MainActor", `documentation/Swift/mainactor`; "SwiftSetting.defaultIsolation", `documentation/PackageDescription/swiftsetting/defaultisolation` | Unannotated code is nonisolated unless default isolation is set; with MainActor default, helpers that must run concurrently need explicit `nonisolated`. The `nonisolated` keyword itself: not found as a page. |
| D | "MainActor"; "Mutex"; "OSAllocatedUnfairLock", `documentation/os/osallocatedunfairlock` | Isolate the state to an actor, or guard it with `Mutex`/a lock in a Sendable holder. `nonisolated(unsafe)`: **no Apple page found**. |
| E | "SendableMetatype", `documentation/Swift/sendablemetatype` | Describes the rule that prohibits isolated conformances on generic types. `InferIsolatedConformances` and MainActor `Equatable`/`Codable`: **no page found**. |
| Metal (if it ever bites) | "MTLCommandBuffer.addCompletedHandler", `documentation/Metal/mtlcommandbuffer/addcompletedhandler` | Handler runs on a driver thread; register before `commit()`; hop to the MainActor explicitly. No Metal page states per-object Sendability; the SDK headers (above) are the evidence. |

Gaps to cover from Swift Evolution proposals or the compiler instead of Apple docs: `sending`, `nonisolated(unsafe)`, `@preconcurrency import`, isolated-conformance inference. (This repo has no `@preconcurrency`.)
