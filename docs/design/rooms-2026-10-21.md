# Rooms design, 2026-10-21: the shared EDX room, the quantification maps (task 4), the precipitate view on the maps

A cloud design pass with the `swiftui-macos` skill, no build. It is the brief for the Mac sessions in "Evening plan" at the end.
Every number is a kit call (SpectroKit 0.8.1, CuboKit 0.8.1, ImagoKit 0.6.1, FormatoKit 0.9.1); the app holds the flow, the views,
the state, the lineage and the words. The sibling document is `macTEM/docs/design/rooms-2026-10-21.md`; the conventions and the
first section are the same in both.

Conventions from the skill, applied in every room below:

- One `@Observable` owner per room in `DSTEMSession` (`TEMSession` in macTEM; MainActor), views read it and hold no facts; the room's transient view state
  (a drag, a window, an export in flight) in a small `@Observable` in `App/` (`SpectroscopyRoomModel` here, `EDXRoomState` in macTEM).
- Everything a view reads is `Equatable` (a snapshot struct with a `version`, as `EDXMapTile` is), so a landed pass that changes
  nothing notifies nothing; caches, task handles and generation counters are `@ObservationIgnored`.
- Each tile, row and marker is its own `View` struct (its own observation scope); a grid's shared values (the mode, the region)
  are read once above the `ForEach`.
- Heavy work runs in a detached task or a `@concurrent` function with a generation token; a result lands only if no newer
  request was made; the kit's `cancelled:` closure is `SpectroCancellation.task`, so cancelling the task cancels the kit.
- Progress comes back through a `@Sendable` closure that hops to the main actor and sets one `Double`.
- A kit error is shown in the kit's words (`LocalizedError.errorDescription`); a pixel the kit could not answer is a nil with a
  reason, drawn hatched and counted in the tile's note; every result carries its `validation` string into the header and the
  export's comment lines.
- Empty: `ContentUnavailableView` with the one verb that fills the room. Loading: a linear progress bar and the file name.

## 1. The shared EDX room (both apps, one pattern)

The same room in mac4DSTEM (Spectroscopy, ⌘6) and macTEM (EDX, ⌘6). macTEM's version landed today cut from mac4DSTEM's
(ADR 028 here, ADR 056/057 there). The pattern below is what both converge on; the differences are listed, nothing else differs.

```
┌ header: file · "whole map, 1.2 M counts, 4096 px" · map mode [int|net|wt%|at%] · tool [▭ ◯ ⬠] · Quantify / Quantified·live · Stop ┐
│ ┌ Mg Kα ───┐ ┌ Si Kα ───┐ ┌ Al Kα ───┐ ┌ Cu Kα ───┐    maps grid: one tile per quantified element, the region drawn on every  │
│ │ ▒▒▒▒▒▒▒▒ │ │ ▒▒▒▒▒▒▒▒ │ │ ▒▒▒▒▒▒▒▒ │ │ ▒▒▒▒▒▒▒▒ │    tile; "3 failed px" footer on an at%/wt% tile; HAADF/scan tile first   │
│ └──────────┘ └──────────┘ └──────────┘ └──────────┘    (mac4DSTEM: the scan-position map from the cube; macTEM: the survey)  │
├──────────────────────────────────────────────────────────────┬───────────────────────────────────────────────────────────────┤
│ spectrum: counts, background, model, line markers, window     │ results: element · line · net ± σ · wt% · at% · validation: none│
└──────────────────────────────────────────────────────────────┴───────────────────────────────────────────────────────────────┘
 inspector: Elements (table, Auto ID, roles) · Region (Whole map, pins, rectangle/ellipse/polygon) · Quantification (method,
            k source computed/typed + Edit…, absorption, thickness, beam energy) · Expert (estimator, background) · Export
```

Flow: open a spectrum image (from the room, its own document) → Auto ID proposes elements → pick and set roles → draw a region
or keep the whole map → Quantify (the pooled fit becomes live) → switch the maps to wt%/at% → export.

State model (the owner, `EDXSession` here, `SpectroscopySession` + `SpectroscopyRoomModel` there):

| Fact | Type | Notes |
|---|---|---|
| the image | `any SpectrumImageSource` | opened off-main with progress; a newer open cancels the older |
| picks, dismissed, region, method | value types, `Equatable` | every edit bumps `generation` and refreshes |
| plot, tiles, rows, markers, fit | snapshots with a `version` | landed by generation; tiles rasterised once per version, cached `@ObservationIgnored` |
| map mode | `EDXMapMode` (`int`, `net`, `wt`, `at`) | wt/at need a live fit; the picker says why when disabled |
| quantified maps | `.idle / .running(Double) / .done(EDXQuantificationMaps, version) / .failed(String)` | one detached pass keyed by (method hash, picks, mask version, net-map versions) |
| auto ID | `.idle / .running / .done / .failed(String)` | restarts when the region changes |

What is app logic: the region geometry (rectangle, ellipse, polygon → a `PixelMask`), the drag, the map raster and colours, the
file names, the words, the lineage (mac4DSTEM). What is a kit call: `SpectrumImageOpener.kind/open`, `ElementWindows`, the net-count
maps, `ElementProposer` (Auto ID), `PooledQuantifier` (the fit), `EDXQuantification.quantifyMaps(intensityMaps:rows:columns:setup:navigationMask:)`
(the wt%/at% maps, mass thickness, atoms), `SpectroscopyExport` (CSV, JSON, method hash), `MSAWriter` (FormatoKit).

Differences by app, and nothing else: mac4DSTEM adds the scan-position tile from the cube, pools over 4D registrations
(`GridRegistration`, `MaskTransport`), records lineage steps, and exports figures through its Figure section; macTEM opens a single
Velox spectrum (`VeloxSpectrumSignals`) and `.msa` beside spectrum images and has no lineage. Candidates for the shared app
package (suite task 8, after both apps converge): the maps grid and tile, the spectrum view, the results panel, the periodic
table, the region overlay, the typed-k sheet, `InspectorRows`. Per app: the owner, the open path, lineage, figure export.

Needs kit task: GMS absorption needs the stage tilt (FormatoKit, Paul's `.dm4`); Velox live and real time per pixel for zeta
(FormatoKit, Paul's `.emd`); a vacuum mask helper (`vacuum_mask`, SpectroKit, the app thresholds the integrated map until then);
`rebin` and the calibration helpers for drift-corrected sums (SpectroKit).

## 2. Quantification maps (ROADMAP task 4; study item 1)

What exists: the Spectroscopy room with int/net maps, regions (rectangle, ellipse, polygon), pins, pools over 4D registrations,
the live pooled fit, typed k, lineage steps, exports; `MapMode.weight/.atomic` listed but never offered (ADR 054 item 3: a pixel
has no σ). What this changes: the two modes are offered once Quantify has run, computed by one kit call, and the composition the
pooled fit gives for a region stays the number with a σ; the map is the picture (its tile footer says "per-pixel, no σ; pool a
region for a σ"), both badged `validation: none`.

```
┌ header: file · region line · map mode [int|net|wt%|at%] · tool [▭ ◯ ⬠] · Quantified · live · Stop ──────────────────────────┐
│ ┌ scan (HAADF / virtual) ┐ ┌ Mg at% ────────┐ ┌ Si at% ────────┐ ┌ Al at% ────────┐ ┌ ρt (kg/m²) ────┐  mass thickness tile  │
│ │ the cube's scan map    │ │ ▒▒▒▒▒▒▒▒▒▒▒▒▒▒ │ │ ▒▒▒▒▒▒▒▒▒▒▒▒▒▒ │ │ ▒▒▒▒▒▒▒▒▒▒▒▒▒▒ │ │ zeta / CL+t only│  only when the method │
│ │ regions and pins drawn │ │ 3 failed px ⓘ  │ │                │ │                │ │                │  gives one            │
│ └────────────────────────┘ └────────────────┘ └────────────────┘ └────────────────┘ └────────────────┘                       │
```

Flow: Quantify (as today) → switch the map mode to wt% or at% → the maps compute from the net-count maps with the live method →
hover a pixel for its composition and the failure reason where there is one → export the maps (CSV, PNG, the Figure section).

State model (`SpectroscopyRoomModel.maps` + `SpectroscopyRoomController`): `quantMaps: QuantMapsState` (`.idle`,
`.running(Double)`, `.done(EDXQuantificationMaps, version: Int)`, `.failed(String)`); one detached pass per
(method hash, quantify-role elements, mask version, net-map versions), cancelled by generation like every other pass; the tiles
rebuilt from `weightPercent[e]` / `atomicPercent[e]` / `massThickness` as `MapTile` snapshots with a version; the raster cache
keyed by (element, mode, version), `@ObservationIgnored`. The method mapping is one pure function in `Core/Spectroscopy`:
`QuantificationMethod` + the fit's k set → `EDXQuantificationSetup` (elements with role `.quantify`; `.cliffLorimer(kFactors:
thicknessNm:)` from `TypedK` or the computed set the pooled fit used; `.zeta` / `.crossSection` with beam current and live time;
`EDXAbsorptionSetting` with `takeOffAngle` from the Velox geometry, absent for GMS until FormatoKit reads the tilt). The navigation
mask is the app's: pixels whose integrated counts fall below a threshold in the Quantification section's new "Maps" row (default
0, off), plus any pixel outside a pooled registration when one is live.

App logic: the mask, the mode picker, the tiles and their footers, the hover readout, the lineage step ("quantification maps":
method hash, mask rule, failed-pixel count), the figure. Kit: `EDXQuantification.quantifyMaps`, `weightToAtomic`, the method
hash (`SpectroscopyExport`). The `@testable` / `package` reach into SpectroKit (`PooledQuantificationInput`) goes with it.

Loading: the tile shows its previous picture dimmed with a bar until the pass lands. Error: `.failed` puts the kit's sentence in
the grid header and keeps int/net selectable. Badge: on every wt%/at%/ρt tile footer and in the maps CSV header. Exports: maps
CSV and PNG per element (region box, scale bar, method hash and validation in the comment lines), the figure (study item 2).
Done when (task 4's line): `SpectroscopyVeloxL4Tests` and `SpectroGoldenTests` pass unchanged against the kit call, one new test
pins a `quantifyMaps` map against the previous per-pixel path, the badge test still finds the key.
Needs kit task: GMS stage tilt and Velox per-pixel live time (FormatoKit, Paul's files); `vacuum_mask` (SpectroKit).

## 3. The precipitate view on the maps (study items 1 and 2)

What exists: objects from the phase map (ADR 019, 038, 045): the Precipitates section in the phase-mapping room, the object table
window, "Show Objects" as a product raster, edge-corrected areal density, CSV. What is missing for the study: the objects over the
other maps (virtual images, the EDX maps), a composition per precipitate class, the thickness that turns areal into volumetric
density, and the outlines in the exported figure. The N_V estimator itself is App work 2 (a new registration) and is not designed
here; the view leaves its row in place, greyed, until it lands.

```
 any scan-grid pane (virtual image · phase map · EDX map)          inspector › Precipitates (phase-mapping room, as today)
┌──────────────────────────────────────────────┐                ┌────────────────────────────────────────────────────┐
│  map with the counted objects as ellipse     │                │ per-phase rows: count · counted · median length     │
│  glyphs in their phase colour, edge and      │  ⟵ one         │ Objects on panes  [✓]  counted only [✓]  labels [ ] │
│  small ones dimmed; hover "#12 β″ 23 nm"     │  overlay,      │ Minimum [4] px                                      │
│  selected table row: bright outline          │  every pane    │ Thickness  t [120] ± [15] nm  source [typed ▾]      │
│                                              │                │ N_V  — (needs the registered estimator, App work 2) │
└──────────────────────────────────────────────┘                │ [Show Objects] [Object Table…] [Pool by Class]      │
 EDX maps: the objects' labels transported to the spectrum grid │ [Export CSV…] [Composition by Class…]               │
 (`MaskTransport`) become one pool per class → a fit per class  │ validation: none                                    │
                                                                └────────────────────────────────────────────────────┘
```

Flow: map phases → objects (as today) → tick "Objects on panes": every scan-grid pane draws the same glyphs → open the EDX maps:
the glyphs sit on the Mg/Si maps → Pool by Class: one pin per phase from the object labels, the pooled fit gives a composition
per class with a σ → type the thickness with its source (or paste macTEM's EELS method JSON as the source) → export the figure
with the outlines and the region box, the objects CSV, the composition-by-class CSV.

State model: `PrecipitateOverlaySettings` (`App/`, `@Observable`, `Equatable` fields: onPanes, countedOnly, labels), window-wide
like `PrecipitateTableSelection`; the glyphs are a `PrecipitateGlyphSet` snapshot (one ellipse per object from `ObjectMoments`:
centroid, major and minor axis, orientation, phase, counted) built once per `sourceID` off the main actor and cached
`@ObservationIgnored` in `AppState`; each pane draws it in one `Canvas` through its own display transform (as the marks are),
so a pane re-draws on zoom, not on a table selection elsewhere; the selection relay (exists) only changes the highlighted id.
`ThicknessEntry` (`Session`, `Codable`, `Equatable`: nanometres, sigma, source text, origin `.typed` / `.eelsMethodJSON(file,
medianTOverLambda, lambda)`) lives on the dataset session, is written to the sidecar and the objects CSV provenance. Pool by Class
is a verb on `AppState+Spectroscopy`: `MaskTransport` moves the label image to the spectrum grid (`GridRegistration`), `PoolBuilder`
makes one pool per class, the existing pooled-fit path runs per pool, cancellable, landed by generation.

App logic: the glyph geometry from moments (no contour tracing), the overlay settings, the thickness entry and its sidecar key,
the CSV, the figure, the lineage step ("pool by class"). Kit: `ObjectMoments` (ImagoKit; the app's segmentation already uses
`Segmentation.label`), `MaskTransport`, `PoolBuilder`, the pooled fit, `EDXQuantification` (SpectroKit).
Needs kit task: the EELS t/λ map (SpectroKit task 16; macTEM's first slice exports the method JSON this view reads); the
Miles-Lantuéjoul areal density moved from `PrecipitateStatistics` into ImagoKit so macTEM's Particles view calls the same
function; `find_contours` (ImagoKit) only if true outlines are wanted over the ellipse glyphs; a thickness record both apps read
(suite). The N_V estimator is app work, not a kit task.

Empty: no phase map → "Map phases to find precipitate objects." (as today); no spectrum image → Pool by Class disabled with "Open
the EDX spectrum image of this scan"; grids that do not register → the kit's `MaskTransportError` sentence. Badge: `validation:
none` on the section, in every CSV and on the figure caption. Exports: objects CSV (exists, gains the thickness line),
composition by class CSV (class, pixels pooled, element, wt%, at%, σ, method hash), the figure as PNG/TIFF/PDF with the glyphs and
the EDX region box (study item 2).
Done when: the overlay draws the same glyphs on the virtual image and an EDX map for one run (a geometry test through the display
transform), a planted two-phase cube with a matching spectrum image gives the planted composition per class within SpectroKit's
tolerance, the thickness entry round-trips through the sidecar, screenshot in the commit.
