# Reference software for EDS Auto ID, EDS quantification and EELS — survey (2026-10-07)

Method: GitHub API / raw files read directly (stars, pushed_at, releases, licences, source), plus web search. "Unverified" marks anything I could not read at the source. Stars/dates are as of 2026-10-07.

## Bottom line first
- **No open tool in this survey documents an automatic element-identification algorithm for EDS.** DTSA-II's author says outright that auto-qual is unreliable and does not ship one; PyMca, eXSpy, NeXLSpectrum and AutoEMX all take the element list as an *input* (details below). So "an open oracle for Auto ID" does not exist as software. What exists is **a graded truth set with known answers** (DTSA-II's `QualSpectra.zip`) plus **Velox's own stored selections** (the owner's 112 SIs).
- For quantification there are good open, documented oracles (DTSA-II/EPQ, NeXLSpectrum, eXSpy, AutoEMX with licence caveat).
- For EELS, eXSpy is the only mature oracle for fitting/thickness/deconvolution; the one open automatic edge-ID tool I found is a neural network (EELS ID, MIT) — not a described physical algorithm.

## 2. Per-tool notes
### 2.1 NIST DTSA-II
- Public domain, "redistributed and/or modified freely", derivative works asked to carry a notice: https://github.com/usnistgov/DTSA2_Documentation/blob/main/LICENSE.md . Source: https://github.com/usnistgov/DTSA-II (+ EPQ library https://github.com/NicholasWMRitchie/EPQ, 22 stars, pushed 2026-09-10).
- **Auto ID: none.** The docs say "In our experience, the auto-qual routines in the vendors software almost work… If you expect better, you'll have to perform qual yourself" and ship practice spectra instead: https://github.com/usnistgov/DTSA2_Documentation/blob/main/documentation.md . What it does have: "Peak search — identifies all ranges of channels at least 3σ above the surrounding background" (same page); source `PeakROISearch.java` (Savitzky-Golay-6 smoothing, per-channel σ-above-background, thresholded ROI): https://github.com/NicholasWMRitchie/EPQ/blob/master/src/gov/nist/microanalysis/EPQLibrary/PeakROISearch.java . This returns channel ranges, not elements. (I did not find any element-assigning class in the EPQ tree listing; a full-source grep was not possible, so "no auto ID" is a strong but not exhaustive finding.)
- **Quantification:** standards-based filter-fit (Schamber-type) + XPP matrix correction (XPP1989Ext / XPP1991 classes), zeta-factor quant (QuantifyUsingZetaFactors) — class names in https://github.com/NicholasWMRitchie/EPQ/tree/master/src/gov/nist/microanalysis/EPQLibrary ; summary of algorithms: https://www.nist.gov/services-resources/software/nist-dtsa-II . Documentation PDFs "DTSA2 Mechanics of Quant" etc.: https://github.com/usnistgov/DTSA2_Documentation . Note it is bulk/EPMA-oriented (standards, k-ratios), not TEM Cliff-Lorimer/zeta thin-film oriented, except the zeta class.
- **Headless/CLI:** Release notes 2026-01-30 (Polaris): "Start Jython scripts from the command line", Jython 2.7.4, Java 24 requirement: https://github.com/usnistgov/DTSA2_Documentation/blob/main/releaseNotes.md . Installer is a Java jar for macOS (nojre variant); Linux/macOS "tested years ago… identical numeric results": https://github.com/usnistgov/DTSA2_Documentation/blob/main/installation.md . Actual CLI invocation syntax: **unverified** (not documented in the pages I read). Launcher script `dtsa2.sh` just runs `java -jar dtsa2.jar`: https://github.com/usnistgov/DTSA-II/blob/master/dtsa2.sh .
- **Inputs:** EMSA/MSA (EPQTools/EMSAFile.java) and SPC; no EMD/Velox. Convert with RosettaSciIO → MSA.
- **Truth set (important):** `QualSpectra.zip` = 31 EMSA spectra of K-glass standards (25 kV, 10 eV/channel, graded easy/moderate/difficult/very difficult) with `Qual answers.txt` listing the true composition (I downloaded and listed it): https://github.com/usnistgov/DTSA2_Documentation/raw/main/QualSpectra.zip . Domain caveat: SEM bulk glasses, not 200 kV TEM thin films.

### 2.2 PyMca
- MIT, ESRF: https://github.com/silx-kit/pymca (LICENSE: https://raw.githubusercontent.com/silx-kit/pymca/master/LICENSE ; note the licence text warns PyQt makes the GUI GPL-conditioned). v5.9.7 on 2026-09-23.
- Fundamental-parameters XRF fit (`PyMca5/PyMcaPhysics/xrf/ClassMcaTheory.py`, `ConcentrationsTool.py`, `Elements.py`, physics via fisx). Fits *given* elements/lines; auto-ID absent. Its "PeakIdentifier" is: given an energy and threshold, list elements with lines in [E-Δ, E+Δ] with relative intensities: https://manpages.debian.org/jessie/pymca/peakidentifier.1.en.html (source `PyMcaGui/physics/xrf/PeakIdentifier.py`). It is a lookup, not an assignment algorithm.
- Designed for XRF excitation geometry (needs source/filters/matrix), so EDS-by-electrons bremsstrahlung background is not its model (reasoned, unverified in docs). Scriptable via `McaAdvancedFit` (https://github.com/silx-kit/pymca). Reading Velox .emd directly: unverified.

### 2.3 eXSpy / HyperSpy / RosettaSciIO (what the repo already pins)
- All GPL-3.0: https://github.com/hyperspy/exspy , https://github.com/hyperspy/hyperspy , https://github.com/hyperspy/rosettasciio .
- RosettaSciIO's `_emd_velox.py` reads Velox EDS spectrum images (sets `signal_type "EDS_TEM"`) and has a `map_selected_element` option: https://github.com/hyperspy/rosettasciio/blob/main/rsciio/emd/_emd_velox.py . It is the only open reader of the owner's files.
- **What exspy lacks for Auto ID:** EDS signal methods are `set_elements/add_elements/add_lines/get_lines_intensity/estimate_integration_windows/estimate_background_windows/print_lines_near_energy` — all take elements as input; `create_model(auto_add_lines=True)` only adds lines for elements already in metadata: https://github.com/hyperspy/exspy/blob/main/exspy/signals/_eds.py , `_eds_tem.py`. The shipped example only prints lines near an energy: https://github.com/hyperspy/exspy/blob/main/examples/EDS/find_EDS_lines.py . (HyperSpy has generic 1-D peak finders; none assign elements — generic-peak-finder claim unverified here.)
- **EDS quant:** `EDSTEMSpectrum.quantification(intensities, method in {"CL","zeta","cross_section"}, factors, absorption_correction, thickness, ...)` — Cliff-Lorimer, zeta, cross-section: https://github.com/hyperspy/exspy/blob/main/exspy/signals/_eds_tem.py . Needs user k-/zeta-factors.
- **EELS:** `EELSSpectrum` has `add_elements`, `edges_at_energy`, `print_edges_near_energy`, ZLP alignment, `estimate_thickness`, Fourier-log/-ratio and Richardson-Lucy deconvolution, `power_law_extrapolation`, `kramers_kronig_analysis`, model with `EELSCLEdge` components: https://github.com/hyperspy/exspy/blob/main/exspy/signals/_eels.py , https://github.com/hyperspy/exspy/tree/main/exspy/components . Edge *lookup near a given energy*, no automatic detection.

### 2.4 AutoEMX (named by the owner)
- Purpose: automated SEM-EDS (acquisition, peak-to-background quantification, rule-based filtering, clustering) developed for Thermo Phenom desktop SEM; benchmarked on 74 single-phase samples, 38 elements, "<5–10% relative deviation"; "Works with spectra from any microscope, although recalibration is recommended": https://github.com/CederGroupHub/AutoEMX . Paper: Giunto et al., Nat. Commun. 17, 9735 (2026), https://doi.org/10.1038/s41467-026-76633-x (not read by me).
- **Licence:** "Free use for non-commercial use only", LBNL custom licence (GitHub reports NOASSERTION): https://github.com/CederGroupHub/AutoEMX/blob/main/LICENSE.txt . → use as an external oracle at most; **never copy code into a GPL-3 app**, and a public repo's reproducibility rule is unaffected only if the harness merely calls it (even that deserves a licence read by the owner — GPL-incompatibility concerns distribution, not private use).
- **Element ID: none.** The single-spectrum script sets `els_sample = ['Bi','Fe','O']`, `els_substrate`, reads BEAMKV/ELEVANGLE/LIVETIME/XPERCHAN/OFFSET from the .msa and fits: https://github.com/CederGroupHub/AutoEMX/blob/main/autoemx/scripts/Fit_Quant_Single_MSA_Spectrum.py . I did not read every core module; no identification step found in `core/fitter/fitter.py` outline.
- **Domain mismatch:** calibrations are for 15 kV Phenom SDD (README: upload "spectrum acquired at 15 kV"); the Velox data are ~200 kV TEM thin film where peak-to-background/bulk absorption assumptions differ.

### 2.5 NeXLSpectrum.jl and espm
- NeXLSpectrum: Unlicense, "Schamber-style filter-fitting", weighted LLSQ, fits characteristic/escape/Compton features, reads EMSA/Bruker/ASPEX/RPL and HyperSpy HDF5 (`hspy.jl`), vector-based quick-quant for hyperspectra: https://github.com/usnistgov/NeXLSpectrum.jl . Documented quant is standards-based (like DTSA-II); no auto-ID found in README or file list.
- espm (https://github.com/adriente/espm): NMF with physical EDXS model; useful for phase separation, not element ID or an oracle for quant.

### 2.6 EELS-specific
- pyEELSMODEL (GPL-3.0, modernised EELSMODEL; model-based quantification with GOS tables, constrained fitting): https://github.com/joverbee/pyEELSMODEL , docs https://pyeelsmodel.readthedocs.io/ . Best independent *second* quant oracle for core-loss.
- EELS ID: "deep learning tool for automated element identification in core-loss EELS", MIT, trained on simulated data, models/data on Zenodo 8004912: https://github.com/arnoannys/EELS_ID ; paper (Sci. Rep. 2023): https://link.springer.com/article/10.1038/s41598-023-40943-7 (not read in full; abstract-level only). A CNN-BiLSTM edge-recognition paper (94.9 % accuracy) also exists, code availability unverified: https://pmc.ncbi.nlm.nih.gov/articles/PMC9789080/ .
- EELSpecNet is deconvolution, not ID: https://github.com/shmouses/EELSpecNet .
- DigitalMicrograph: Gatan's script-library page returned a bot checkpoint (not read; contents and licence **unverified**): https://www.gatan.com/Software/Scripts/DigitalMicrograph-Library . EELSTools (Mitchell & Schaffer, v2.0, 2012, "20 EELS Tools", tested on GMS 1.83/2.10, licence not stated; includes an EELS edge chart/calculators): https://mail.dmscripting.com/eelstools.html . FELMI database (290 scripts, no stated licence): https://felmi-zfe.at/dm-script-database/ . All need GMS on Windows/macOS-Intel-era DM; unusable headless, and licence-unclear → **neither port nor automate**; at best a human cross-check.

### 2.7 Velox and TIA
- Closed; I found no published description of Velox's or TIA's auto-ID/quantification algorithm (unverified). The repo's own measurement against Velox's stored selections (`tools/autoid-velox-check`, 78 files, precision 34 %, recall 45 %, from the 2026-10-07 commit message) shows those selections are a *noisy human-curated reference*, not truth: agreement with Velox ≠ correctness.

## 3. How to get a truth for the owner's 112 Velox .emd
1. **Stored selections** (already done by `tools/autoid-velox-check`): useful as "what a Velox user picked", with the caveat above.
2. **Quant:** read the SI with RosettaSciIO (`sum_EDS_detectors=True`), sum spectra over regions, run exspy `EDSTEMSpectrum` `get_lines_intensity` → `quantification(method="CL"/"zeta")` with explicitly stated factors (Velox's own Cliff-Lorimer settings are stored in his file — the repo has them as a fixture). Compare at-% to Velox's stored quantification table if present. Gap: k-factors must be identical or the comparison tests the factors, not the code.
3. **Independent second quant:** export a region sum as MSA, run DTSA-II (Jython, command line) or NeXLSpectrum in filter-fit mode against the same element list; needs standards or the zeta/theory route, so expect larger disagreement on thin TEM films (reasoned, unverified).
4. **Auto-ID truth:** only the DTSA-II Qual set has real truth, but it is 25 kV SEM bulk glass. Use it to score the app's Auto ID *as an algorithm* (recall of listed elements, false positives per difficulty class), then use Velox selections for TEM-domain agreement only.

## 4. Recommendation
For EDX **Auto ID**, pin DTSA-II's `QualSpectra.zip` (public domain, 31 spectra with answers, committed under `docs/archive/` or a fixture; ~156 kB, no Java needed — just MSA files and a text answer key) as the *only true oracle*, scored per difficulty class, and keep the Velox stored selections as a labelled "agreement with Velox", never as truth; effort ≈ 0.5–1 day to extend the existing `autoid-velox-check` harness to read MSA and parse the answers (the Swift side already exists; MSA parsing is trivial). For EDX **quantification**, keep **eXSpy** (already pinned, GPL, reads Velox) as oracle #1 — extend `tools/edx-pins` with `quantification(method="CL"/"zeta")` pins, ≈ 1 day — and add **DTSA-II (EPQ) via its new Jython command-line mode** as an independent oracle #2 for filter-fit/XPP on MSA exports, ≈ 2–3 days including the Java 24 + Jython invocation (CLI syntax unverified; budget a spike) and reconciling standards-vs-factors differences; **NeXLSpectrum.jl** is the lighter alternative (Julia install, no GUI) if Java proves awkward. Do **not** pin AutoEMX (non-commercial licence, SEM-15 kV Phenom calibrations, takes elements as input, so it adds neither auto-ID nor TEM truth); at most run it once by hand as a curiosity. For **EELS later**, pin **eXSpy EELS** (`edges_at_energy`, `estimate_thickness`, power-law/model fit, Fourier-log/ratio deconvolution, KK) as the main oracle — effort ≈ 1–1.5 days, mirroring the exspy EDS harness, because it is the same venv — with **pyEELSMODEL** (GPL, GOS-based model fit) as a second opinion on core-loss quant (≈ 1–2 days), and treat **EELS ID** (MIT, neural net, TensorFlow dependency, Apple-silicon install friction noted by its README) only as an optional comparison for edge ID, not as ground truth; skip the DigitalMicrograph script libraries (licence unclear, needs GMS, not scriptable headless).
