## (3) The fix
Correct in kind (preview-only, labelled). Must-fix items:
- M1 Threshold rule. `spread <= 1e-5 * mean` is a tuned cutoff of our own (≈84 Float32 ulps at 1); CLAUDE.md's threshold rule applies. Replace with a DERIVED bound: the reader has already rounded every pixel to Float32 (relative error ≤ 2⁻²⁴), so a total is only known to ±2⁻²⁴·Σ|p|; declare the total uninformative when spread ≤ 2·2⁻²⁴·max Σ|p| (two totals' worst-case rounding). Real file: spread 1.29e-8 ≤ 1.19e-7 → triggers. Pure "all Float(total) equal" is exact for blackness but would display 1-ulp rounding noise as a binary image when totals straddle a Float boundary (the lane's own fixture does: totals spread 9.97e-8, TWO distinct Float32 values — testsim.log), so the derived bound is the better exact criterion. Accumulate Σ|p| alongside total (one more add per pixel).
- M2 Window geometry. "Middle eighth of each axis" is another constant of our own and gives an image unrelated to anything else on screen. Use the app's own default virtual-detector geometry instead: circle at detector centre, r = min(qx,qy)/4 (AppState+Open default aperture) — then the fallback preview is a subsample of what the virtual-detector pane shows by default (measured on the preview grid: 0.9970–0.9999, rel. span 2.9e-3, well above Float32 resolution, so it stretches to a full-range image).
