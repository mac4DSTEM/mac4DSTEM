### 4. Info tab: dtype says uint64, Size line is labeled "(f32)" with no explanation
Screenshot: B06-crop-dtype.png, B06-crop-size.png (crops of B06-sisige-info.png)
What I saw: Info tab for downsample_Si_SiGe_exp.h5 reads "dtype  uint64" and, two rows down, "Size (f32)  655,4 MB". 50×200×128×128×4 bytes = 655,360,000 bytes, i.e. the 655.4 MB figure is computed as if every element were 4-byte float32 — it does not match a uint64 (8-byte) footprint, which would be roughly double. So "Size (f32)" is most likely reporting the in-app working size after mac4DSTEM casts the source data to float32, not the on-disk size of this uint64 file — but nothing in the panel says that. A scientist skimming Info for the dataset's real disk footprint (e.g., before copying it, or to sanity-check a uint64-vs-float32 precision choice made on ingest) gets a number that silently means something other than what the visible dtype implies.
Why it matters (senior scientist / reproducibility persona): this is exactly the kind of small mismatch that erodes trust in the Info panel as a provenance source — I would want the label to say "(after cast to f32)" or similar, or show the on-disk size next to the on-disk dtype.
Severity: papercut
