## Why this session exists

mac4DSTEM classifies every scan position of a 4D-STEM dataset into a phase
(Al matrix, θ′ edge-on, θ′ face-on, T1) and turns the class map into
precipitate objects (count, length, area fraction). On the published truth
set (Thronsen et al., *Ultramicroscopy* 255 (2024) 113861; data Zenodo
10.5281/zenodo.6645396, CC BY 4.0) the app mislabels **1.81 %** of positions
on a stride-3 subsample — close to the paper's own 0.96–1.75 % band — yet its
**object counts are far off** (T1 62 vs 37 objects, median length 8.6 vs
23.1 px; θ′ face-on 70 vs 3). Area fraction is right. Record:
`docs/archive/v3/precipitate-overnight-2026-09-23.md`.

Two things may explain part of that gap without any classifier error: the
truth was built from thresholded virtual dark-field images **with small
regions deleted as noise**, and stride-3 sampling breaks or drops thin
needles. This session measures that, and asks the question that decides the
project's direction: **at ~1 % per-position error, do the paper's own four
published maps get object counts and lengths right?** If they don't, the
per-position metric was never the right pass bar for anyone.

### T2 — The direction check: published maps vs truth, at object level

(`datasetA_phasemap_{ANN,NMF,TMP,vectors}.hspy`) from Zenodo 6645396
(HyperSpy files are HDF5; read with `h5py`, find the data array and the
class coding — confirm it against the paper and the truth's own class
integers: 0 Al, 1 θ′ edge-on, 2 θ′ face-on, 3 T1, 4 not indexed/disagreement;
verify the maps use the same coding, and state it). At **full resolution
(512×512)** compute for the truth and each map:
- per-position error (their definition — reproduce the paper's reported
  per-method figures first; if you cannot, say by how much and stop trusting
  your reading until explained);
- per class: object count, median / quartile lengths, area fraction;
- split/merge/vanished counts against truth objects (a truth object
  overlapping >1 predicted object = split; the reverse = merge; no overlap =
  vanished — mirror the definitions in the overnight record);
- the same after applying **the truth's own small-object convention** to the
  map (the minimum sizes the authors used when cleaning the truth, from the
  paper/notebook — state exactly which rule you applied and why), so the
  comparison is like for like.
Then repeat everything on the **stride-3 subsample** (every 3rd row and
column, as `tools/thronsen-dataset/make_truth.py` does) to measure what
sampling alone does to counts and lengths.
Deliverable table: rows = truth / ANN / NMF / TMP / vectors, at full res and
stride 3, with and without the cleanup convention. Then the headline question
answered with numbers: at their per-position error, **do the published
methods get object counts and lengths within X of truth?** (report the
distribution; do not pick X). Report: `docs/cloud/2026-09-23/T2-direction-check.md`.
