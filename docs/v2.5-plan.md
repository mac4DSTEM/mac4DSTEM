**Sources:** the owner's two 2026-09-01 reviews (`mac4DSTEM-ui-review`,
`mac4DSTEM-v3-architecture-brief`, code+docs) and the 2026-09-02 read-only

## 1. Naming

- **v2.0** ships now, as is.
- **v2.5** is the internal codename for the architecture consolidation. Its
  increments release as v2.1, v2.2, … No new science.
- **v3.0** is reserved for the owner's feature plan and bumps when the first
  of those features lands on the new legs.
- Process and architecture docs are **version-free**: `docs/v3-development-process.md`
  becomes `docs/development-process.md` and replaces the current one. Only the
  contract and the status file carry a version.

## 3. Merged UI findings, in trust order

Stale and dropped: the colormap-control blocker (fixed and verified on
screen 2026-09-02). "Runtime" marks findings only visible in the running app.

1. **Provenance is inherited and inferred.** Restored "Quantitative" badges
   survive onto new images; unknown kinds default to quantitative
   (`App/AppState.swift:755`); missing Q units fall back to `1/nm`
   (`UI/DiffractionView.swift:174`). One defect: scientific status lives in
   strings and flags, not on the product. **This is the architectural seam.**
2. **ACOM confidence is not gated** (runtime). Reliability 0.07 renders as a
   saturated IPF map. Mask below threshold by default, threshold on the
   colorbar chip, fraction-above-threshold in the footer facts.
3. **Crystal replayed as carbon with gold's lattice** (runtime). **Gate D
   2026-09-02, closed:** not a replay defect — carbon was the session's
   picker choice and replay cannot substitute Z. The gate exposed the real
   hole, a drifted lattice constant replaying under the same id, now refused
   by name (`lattice_a` in the recipe). Residual: imported-CIF id collision
   by filename (`docs/open-items.md`).
4. **Calibration state is contradictory.** "Core calibrated" =
   origin+rotation (`UI/ContentView.swift:1187`); "Calibration is complete"
   (`UI/CalibrationReadinessView.swift:21`) uses another rule. Four
   vocabularies: Missing / Not quantitative / Imported from file / Core
   calibrated. Replace with task-aware readiness ("Ready for qualitative
   DPC; still needed for quantitative iDPC: accelerating voltage, Δq") plus a
   three-state per-item scheme: **Not set / Estimated / Measured**.
5. **Units and labels.** "0 kV" for an unset voltage
   (`UI/ContentView.swift:151`); "A^-1" on screen; "Categorical" chip on an
   IPF map (`App/AppState.swift:750`); hexagonal IPF legend vs colour mapping
   (earlier review, unverified here); raw result-kind strings in Results.
   All resolve when labels are formatted from typed semantics. Wording:
   "Accelerating voltage", "R–Q rotation not calibrated", "Reciprocal-space
   sampling (Δq)", "Real-space scan step (ΔR)".
6. **Phase is falsely linear.** Ptychography hidden behind parallax stages;
   completed stages not revisitable; "Reconstruction Ready" rendered as a
   disabled button. Split into **DPC & iDPC / Parallax / Single-slice
   ptychography**, shared prerequisites, separate state.
7. **Trust notices in the wrong place.** Invalidated-calibration and
   session/view-mismatch warnings hide in a closed inspector; the inspector
   shows annulus radii in Prepare and a "Diffraction" histogram beside an
   ACOM pane (runtime). Rules: warnings sit above the affected image and in
   Results; the inspector describes the focused pane only.
8. **Consistency debris.** Two Prepare subtitles
   (`App/ProductWorkflow.swift:34`, `UI/ProductWorkspaceViews.swift:359`);
   "Calibrate Rotation" vs "Measure R–Q Rotation"; "Log counts" (histogram
   y) vs "log display" (intensity); footer log duplicating Promote Run
   diagnostics; truncation at the default divider; footer "Cube" meaning the
   theoretical f32 size; absolute paths in status; A/B comparison with
   independent normalisation; mixed axis-order labels; a top-level
   Workspace menu (fold into View).
9. **Origin-fit fallback hides a NaN.** Where py4DSTEM returns NaN (no
   qualifying threshold), `Core/Analysis/OriginCalibration.swift:62` falls
   back to the middle threshold so a radius always appears; readiness does
   not mark it as a fallback. Gate D owed, same family as the probe radius.

Fix now on v2.0: 3 (must), 2, 6, 8; 9 is a Gate D whenever convenient. Do **not** patch 1, 4, 5, 7 on the
current facade — they are what v2.5 is for.

## 4. Architecture: agreed, and the three disagreements resolved

**Agreed by both analyses.** `AppState` → composition root and window
coordinator. `ContentView` → composition plus focused task views. A typed
task registry (id, required dataset/calibration capabilities, upstream and
produced product kinds, invalidation keys, one readiness result) replaces
readiness rules re-derived in views. `ScientificProduct` is an immutable,
self-describing value (payload, axes, value semantics, frame, calibration
snapshot, validity, provenance, algorithm record); `ProductPresentation`
holds colormap/window/overlays. Persistence serialises domain values, never
the live object graph. Retired `mac4DSTEMUITests` + `tools/ui-qc-playthrough`
are deleted first. Harnesses get one source manifest. Feature work waits
until the seams are proven. The brief's twelve anti-bloat rules and its
metrics list apply unchanged.

**D1 — first seam.** Brief: `ScientificProduct`. Session: package split.
**Both, split first.** It is mechanical (see §2), takes days, and turns
"Core has no UI knowledge" into a compile error. Three local packages:

- `DSTEMCore` — Data, Compute, Analysis, Crystal, Shaders. No UI, no session.
- `DSTEMSession` — calibration, products, recipes/replay, operation lifecycle.
- the app target.

`swift build` / `swift test` from the shell removes the DerivedData disk
floor (the exit-69 refusals) and makes agent turns cheap. `ScientificProduct`
then lands in `DSTEMSession` as the brief specifies, one product at a time.

**D2 — scale.** Brief: 6–9 months full time for the full proposal. **Take
its own "foundation" option, 12–16 weeks, and stop there:** package split,
product model with two migrated workflows, dataset/calibration/operation
owners, the task registry, the Phase split. **Defer** the HDF5/EMD writer
decomposition (2 746 tested lines behind a stable facade — wrap, don't
split) and the harness-into-package-tests move (trivial after the split).
Everything beyond ships as v3 features exercising the new model.

**D3 — ceremony.** Brief keeps all gates. **Keep Gate D unchanged** (a
written diagnosis is cheap and has paid for itself three times). **Gate B
only** for changes that alter a number in `DSTEMCore`. **Retire Gate A**
fourteen-agent fleets; one reviewer at a lower tier. **Track B**: a
five-minute drive of ≤10 rows after each user-visible slice; the full
checklist once per tag. Session records → commit message + one paragraph in
`docs/decisions.md`.

**Registry = recipe engine.** The brief's task registry and the session's
"one execution path" are the same object: the registry declares what a task
needs and produces; replay already executes tasks from recorded parameters.
The live UI runs through the same path. That deletes the live-vs-replay
duplication in `AppState` and the class of bug behind finding 3.

  only for `DSTEMCore` numbers.

**c. Invariants (§4, restated)**

- Payload, axes, value semantics, frame, calibration snapshot, validity, provenance, algorithm record travel together as one immutable value.
- Presentation (colormap/window/overlays) is a separate value, never folded into the product.
- Persistence serialises the domain value, never the live object graph.
- No view derives units, frame, validity or provenance from strings.

**d. Adapter plan**

1. `ScientificProduct` replaces the compute-side publish (a): `runVirtualDetector` constructs it directly instead of setting `resultImage`/`restoredResultInfo=nil` separately. Deletion condition: once every `analysisMode` publishes a `ScientificProduct`, delete `resultImage`/`resultRGBA`/`restoredResultInfo`/`navigationResultInfo` and their didSet coupling.
2. `AppState.displayedProduct` (671) becomes the accessor that unwraps the stored `ScientificProduct`, not an assembler — `currentScalarResultMetadata`'s per-mode switch (ResultExport.swift:1389) moves into each compute call site. Deletion condition: `currentScalarResultMetadata` has zero call sites.
3. `exportResultImage` reads the same `ScientificProduct` as `publicationCaption` already does. Deletion condition: `exportResultImage`'s raw-field branch (179-186) is gone; one source for both halves.
4. Sidecar read/write take a `ScientificProduct` codec instead of `ScalarResultMap`'s discrete fields. Deletion condition: `ScalarResultMap`/`RGBAResultMap` become the codec's wire format only, never constructed outside `BraggVectorEMDWriter`.
