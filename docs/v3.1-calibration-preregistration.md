## The theme, sequenced

`ROADMAP.md` priority-1 "Calibration foundation" is four sub-items. Gate B
capacity is one campaign at a time, so they are sequenced, least-risk first.
The **origin validity mask leads** (owner, 2026-09-17): it is owed by a
recorded decision, it clears a live open item, and — done as pure disclosure —
it moves **no shipped scientific number**, so it lands the v3.1 scaffolding
without spending the single Gate B slot.

1. **Origin validity mask** — this document. Disclosure only, unit gate.
2. Recover the discarded CoM beam centre in `probeSize` — **Gate D DIAGNOSED
   2026-09-17, conclusion: no forced change; parked.** `probeSize` returns
   `(r, x0, y0)`; the two `OriginCalibration` callers keep `r` and drop `x0/y0`
   (`:516,573`). py4DSTEM uses that CoM as the default origin centring the probe
   cross-correlation kernel (`braggvectors/probe.py:502-556`, `if origin is
   None`). **What the code actually does** (verified, not inferred): the
   *file*-probe path already centres on the CoM (`AppState.swift:4540-4545`,
   exactly py4DSTEM), but the *measured*-probe path centres on `referenceOrigin`
   (`:4496`) — which prefers fitted maps → recorded mean → **aperture** →
   geometric middle (`Calibration.swift:749-763`). So in the app the discarded
   CoM would only change the kernel centre in the **aperture-vs-CoM** case, and
   the CoM is *not obviously better* there: `probeSize`'s CoM is taken on the
   mean/current pattern and "counts Bragg disks as probe area"
   (`QCalibration.swift:110`), so on a Bragg-heavy ROI it can be pulled off the
   beam, where the user-placed aperture is not. The safe part (a CoM fallback
   before `.geometricMiddle`) only affects headless paths with no aperture.
   **Conclusion:** a science change here is marginal and two-sided; not justified
   without evidence the aperture-vs-CoM case helps on real data, and it would add
   a branch to a path that is currently one clean derivation. Parked — measure
   CoM-vs-fitted-mean on the resident cubes before ever touching it. (Correction:
   the cubes ARE resident — `References/{demo-dataset,training_dataset}` — so this
   CAN be measured; it simply is not worth a forced change now.)
3. Beamstop-tolerant origin (`get_origin_friedel`) — new py4DSTEM port, Gate D
   + a parity harness; unblocks Medipix/EMPAD beamstop data.
4. Vacuum probe from a separate scan — largest; new data-loading path + UI; the
   real fix for the MgO disk-radius finding. Its own pre-registration when reached.

Each later item is pre-registered as its own step before its code; this file
registers item 1 in full.

## Item 1 — Origin validity mask

**What it is.** `OriginMaps` today carries the *scalar* `excludedFraction`
(`Calibration.swift:456`) and nothing about **which** scan positions the robust
trim excluded. But the trim already computes that per-position mask:
`TrimmedFit.kept: [Bool]` (`OriginCalibration.swift:188`), and `excludedFraction`
is *derived from it* (`:204-206`). The mask is discarded — the two `OriginMaps`
constructors pass `fitted.excludedFraction` and `fitted.keptResidual` and drop
`fitted.kept` (`:540-544`, `:594-598`). This increment surfaces that already-
computed mask on the product. Nothing more: the fitted origins
(`fittedX/fittedY`), the fraction, and the residual are byte-identical
before and after.

**Why it is owed.** The 2026-08-28 admit-with-fraction decision
(`q-calibration-design.md:440-457`) bound the app to carry the exclusion
evidence *on the product*, so it "survives export and reopen" and "reach[es]
the reader who sees the number." It shipped as a scalar. A scalar cannot
distinguish a scattered exclusion from a spatially clustered one — which is
precisely the gap open item "the trimmed fit is blind to spatially clustered
failure" names (`open-items.md`, origin-fit holes (c)). The per-position mask
is the same disclosure decision carried from a number to a map.

**What it touches, and who owns the state.**
- `OriginMaps` (`Core/Data/Calibration.swift:433`) — a new optional field
  (D1 below) and its init parameter. `OriginMaps` is the owner of the state; it
  already owns `excludedFraction`, so the mask lives beside it, not in `AppState`.
- The two `OriginMaps` constructors in `OriginCalibration.swift` (`:540`,
  `:594`) — pass `fitted.kept` through.
- The product surface that displays the origin fit (the origin-map display /
  workspace inspector). Presentation, D4 below.
- **Not touched this increment:** `BraggVectorEMDWriter.swift` / `H5Reader.swift`
  (sidecar/EMD I/O). Persistence is deferred — D3.

**Off by default.** Trivially satisfied: this increment is disclosure only.
No analysis reads the mask to decide anything, so no computed number can move.
The moment a later increment makes the mask *gate* a computation (e.g. refusing
to consume an interpolated origin), that increment is a Gate D of its own with
an independent refuter.

**The tests, written and broken first.**
- `originValidity` carries `TrimmedFit.kept` unchanged from a trimmed fit —
  break-first by dropping the field at the constructor → red.
- The new field and the existing scalar cannot silently disagree: assert
  `excludedFraction == 1 - mask.trueCount / mask.count` on a fit with a planted
  clustered outlier set, and that the mask marks exactly the planted positions.
- Nil-when-not-from-a-trim: an imported py4DSTEM / file / session `OriginMaps`
  carries `originValidity == nil`, mirroring the `excludedFraction` nil contract
  (`Calibration.swift:446-449`) — the app must not invent a mask nobody computed.
- Reconcile the case count against `func test` per file (the stale-bundle trap,
  `open-items.md`); grep the run log for each new test's own name.

**Gate.** Disclosure only → **unit gate** (`tools/run-tests.sh unit`, plus
`core` for the package build). Not a Gate D trigger: no scientific number moves,
placement/presentation only. Stated as unverified on screen until the owner
drives the display (D4).

**Landed 2026-09-17 (Core disclosure), unattended.** `OriginMaps.originValidity:
[Bool]?` added beside `excludedFraction`; populated from `TrimmedFit.kept` at the
two `OriginCalibration` trimmed-fit constructors (`tiledRun`, `run`). Tests:
`CalibrationDisclosureTests` pins the init carry and the nil contract (default +
`appOriginMaps` bridge); `ProbeSizeTests` drives `tiledRun`/`run` on a
displaced-beam fixture and pins the **production** carry — the mask marks the
three trimmed positions and equals an independent recompute of the trim on the
pipeline's own measured origins. Break-first: M1 (init drops the field) and M2
(bridge invents a mask) redden the disclosure tests; **M3 (both production carries
reverted to nil — the feature dead) reddens both production-path tests** and no
other. Gates: unit **693 / 0 / 2 = 695**, core exit 0, inventory exit 0.

**The adversarial pass earned its keep.** An independent 4-lens review
(no-number-moves, faithful-carry, wire-format-frozen, tests-honest) confirmed the
first three clean and **caught a real hole in the fourth**: the original three
tests built `OriginMaps` by hand, so they exercised only the init assignment —
reverting the two production carries left them all green (M3 would have passed).
The `ProbeSizeTests` production-path tests above are the fix, and a tautological
mask⇄fraction test was removed.

**D4 landed 2026-09-17 (count only).** The Prepare "Positions used" row now shows
the absolute count from the mask — "142 of 150 positions" — via
`PrepareSettings.positionsUsedValue`, mirroring `WorkspaceInspector.validityLabel`,
falling back to the percentage when a restored session carries no mask (D3).
Unit-tested (`testPositionsUsedValueShowsTheCountWhenTheMaskIsPresent`,
break-first M4). **Unverified on screen** (unattended). The full spatial overlay —
render the origin fit over the scan grid with excluded positions greyed via the
existing `DisplayedProduct.validityMask` → `MetalImageView` path — is a larger
follow-on (a new product-construction path), not built.

**Step-3 verdict — measured 2026-09-17 on four on-disk cubes, PASSES.** The claim:
the mask distinguishes a *scattered* exclusion (isolated bad measurements) from a
*spatially clustered* one (a real defect the scalar hides — origin-fit hole (c)).
Measured with `tools/origin-fit-diagnostics trim-sweep` at the shipped default
trim (`step3-trimsweep*.log`):

| cube | excluded | maxGap (spatial support) |
|---|---|---|
| `AlMgSi_demo` (100×100) | 0.6 % | 1 — scattered |
| `Si-SiGe_calibrated` (17×77) | 15.7 % | 1 — scattered |
| `polycrystal_2D_WS2` (128×128) | 15.3 % | 3 — mild clusters |
| `sim_Au` (84×100) | 10.6 % | 5 — clustered |

The excluded fraction (0.6–15.7 %) and the clustering (`maxGap` 1–5) vary
*independently*: Si-SiGe and sim_Au exclude a similar fraction, but Si-SiGe's are
scattered (`maxGap 1`, isolated noise) while sim_Au's cluster (`maxGap 5`). The
scalar cannot tell those two apart; the mask can, and that is exactly hole (c).
So the mask earns its place on **real** data, not only the synthetic
`DisplacedBeamFourDDataSource` tests. (The clusters here are modest — a run of ~5
positions, not a thrown quarter-scan; a dramatic clustered failure is still only
synthetic.)

## Decisions owed to the owner

Defaults are proposed; each is marked so the owner can overrule on sight.

- **D1 — representation.** `originValidity: [Bool]?` aligned index-for-index
  with `fittedX/fittedY` (`true` = a kept measurement). *Proposed default;
  mirrors the internal `kept` exactly.*
- **D2 — semantics.** The mask means the robust trim's `kept`: `false` = this
  position's fitted origin is interpolated from neighbours, not from a kept
  measurement — it does **not** separately distinguish "unmeasurable" from
  "measured-but-trimmed". *Proposed default; the honest minimal meaning.* Owner:
  whether a later increment should split those.
- **D3 — sidecar persistence (a wire-format decision, plan §8, owner's).** This
  increment carries the mask **in memory + on the product only**; it writes no
  sidecar/EMD field, so a restored session's mask reads nil — consistent with
  "the fit-anyway mark does not survive a round trip" (`open-items.md`). Adding
  the field touches the parked `BraggVectorEMDWriter` split (high HDF5 risk).
  Owner: whether/when to persist it.
- **D4 — on-screen.** A minimal validity indicator on the origin-map display (a
  count, or an excluded-position overlay). *Presentation — owner drives it;*
  unverified on screen until then.

## Item 3 — Friedel origin (`get_origin_friedel`)

**Pre-registered + Core algorithm LANDED 2026-09-17.** A beamstop-tolerant origin
finder ported from py4DSTEM's `get_origin_friedel` (`process/calibration/origin.py`).
The pattern is centrosymmetric about the beam, so the peak of its self-correlation
`Re(IFFT2(FFT2(im)²))` sits at twice the origin; with a boolean `mask` false under a
beamstop, py4DSTEM's three-term masked form recovers the origin even when the direct
beam is occluded — the case the centre-of-mass origin cannot serve.

**What it is / off by default.** A NEW, opt-in method
(`Core/Analysis/FriedelOrigin.swift`, `FriedelOrigin.origin(pattern:height:width:mask:)`).
Additive: it changes no existing origin, and nothing computes it until a caller asks.
Returns the origin in the pattern's own (row, col) frame; the app-frame swap is applied
at the call site, exactly as `appOriginMaps` does.

**What it touches.** New file only, plus the harness `tools/friedel-origin-test/`, a
`friedel` group in `sources.manifest`, and the `scientific` array. **Not yet wired to
`AppState`/UI** — that follow-on adds a full-scan loop, an origin-method choice, and a
beamstop-mask source; `FriedelOrigin` is a validated engine awaiting that wiring (the
harness's use counts as a reference, so `inventory` does not flag it, but it is not on
the app's own code path yet).

**Tests, written against py4DSTEM.** `tools/friedel-origin-test` (gated `scientific`):
`reference.py` asserts the pinned-source contract (12 exact expressions), independently
transcribes `get_origin_friedel` in numpy, and plants a sub-pixel asymmetric origin on a
centrosymmetric pattern — clean and with a beamstop. `main.swift` asserts recovery
(≤ 0.5 px of the planted origin) and parity (Swift == the numpy transcription, ≤ 0.1 px).
Measured 2026-09-17: clean recovery **0.027 px**, parity **7e-7 px**; masked recovery
**0.021 px** (through the beamstop), parity **1e-6 px**. Break-first Mf1 (complex square
a²−b²→a²+b², 23 px error) and Mf2 (row/col axis swap, 3.3 px error) both caught. One
DEVIATION note (wraparound subpixel indexing, identical for interior peaks).

**Beamstop mask — LANDED 2026-09-17, and it was not a design decision after all.**
py4DSTEM has a dedicated `DataCube.get_beamstop_mask` (`datacube.py:1013`): percentile-
threshold the mean DP, fill holes both ways, drop the border, dilate by a distance
transform. Ported exactly to `Core/Analysis/BeamstopMask.swift` — the scipy morphology
reproduced as a 4-connected flood fill and an exact Euclidean-distance test. The harness
pins it **pixel-identical** to scipy on a synthetic (threshold, pattern-fill and dilation
each mutation-caught), and — the strong evidence — it is **pixel-identical to scipy on the
real Au_ref beamstop cube** (1453 of 4096 px, 0 disagreements; step 2 the dim-region fill
moves 3 px there, step 3 moves 157). On that cube the Friedel origin recovers the beam
behind the stop; the CoM stays close too because this stop is a thin arm, so it is a
"Friedel is correct through a real beamstop" validation, not a "CoM fails" one.

**Decisions owed (the app wiring, a follow-on).** Where the origin-method choice lives
(detection settings, not `AppState`); whether the Friedel origin feeds the same
`OriginMaps` path or its own; and the mask's threshold/distance defaults (py4DSTEM's
0.25 / 2 px, exposed to the user or fixed). Gate D when it becomes an origin an analysis
consumes; the parity harnesses are its Gate-B-grade validation.
