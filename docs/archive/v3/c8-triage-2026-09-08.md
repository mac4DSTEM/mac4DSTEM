## 3. Dependencies and data-model assumptions

- **Learned detector (C7):** none of the four surviving pieces touch it.
  `PrecipitateReflections.find` reads only the MAX pattern and calibration
  origin; `PrecipitateSegmentation`/`PrecipitateStatistics` operate on
  whatever scalar scan image is displayed; `DiffractionEmbedding.compute`
  streams the raw cube directly (`DiffractionEmbedding.swift` header:
  "Streams the cube exactly like VirtualDetector/TiledDiskDetection").
  `DiskLabelStore`/`DiskLabelRows`/`AppState+DiskLabels.swift` are the one
  piece that *does* depend on the learned detector's candidate list — moot,
  they are dropped.
- **Classical peaks (Bragg detection):** no dependency in any surviving
  piece — confirmed by reading each file's inputs above.
- **§1.5's four unsettled questions, concretely:**
  - *Per-object result in a field-per-scan-position model:* `PrecipitateProduct.objects: [PrecipitateSegmentation.Object]` (`Session/PrecipitateProduct.swift:65`) is a genuine per-object list (id, centroid, length/width, orientation, `touchesEdge`) held only in the in-memory session type — it has no counterpart in `DisplayedProduct`, which is scan-position-indexed. This is exactly the assumption the design session is meant to settle; the branch ships it without settling it.
  - *How it exports:* `git diff main...ml/disk-detector -- mac4DSTEM/Support/ResultExport.swift` adds only a `("precipitate_objects", "Precipitate objects", "object_id")` kind/name/units triple for "Save to Results" — this saves the rasterised label *image*, not the object list. The list's fields (length, width, edge flag) never leave `PrecipitateProduct`.
  - *How it lives in a sidecar:* no reference to `precipitates.` or `diffractionGroups.` exists anywhere under `mac4DSTEM/Support/*.swift` (checked by `git grep`). `PrecipitateProduct.clear()` (`:186-195`) drops `objects`, `density`, and the reflection list on dataset change with nothing written to the sidecar first — a save/reopen loses the per-object result and the density entirely; only the label image (if "Save to Results" was pressed) survives.
  - *What a density refuses when it cannot state its denominator:* the one part of §1.5 this branch answers honestly — `PrecipitateStatistics.density()` returns `arealDensity: nil` without a positive, finite `pixelSize`. But per item 1 above, when it *can* compute a value, the denominator it names (`product.validityMask`) is not provably the same region the objects were segmented from.
  - Diffraction groups is a smaller version of the same class of problem: its result is a per-scan-position categorical map (`payload: .scalar(DiffractionEmbedding.groupMap(result))`), which *does* fit the existing field-per-position model — but group *identity* is not stable across reruns at different k (the type's own comment at `Session/DiffractionGroupsProduct.swift:44-46`: "raising Groups from 4 to 8 left the k=4 group sizes on screen" — the reason `isStale` was added at all), which is its own unresolved data-model question, just a narrower one than precipitates'.
