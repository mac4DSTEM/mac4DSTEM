## 2. Phase 1 on screen — first look (1470 × 923, demo fixture, dark)

Works as decided: inspector from toolbar to bottom edge; toolbar = dataset
menu + two panel toggles; centre header = breadcrumb left, Save to Session

## 5. What landed (items 1, 4, 5)

- `WorkspaceNavigation`: `availableWindowWidth` (measured, not persisted),
  `navigatorFits` / `inspectorFits`, `navigatorIsVisible` /
  `inspectorIsVisible` = intent AND fit. `showToolsPane` /
  `showInspectorPane` are intent only.
- `WindowAnatomyPolicy`: budget at the ideal column widths, a function of
  window width alone (no feedback through the centre column's own width).
- `ContentView`: the split view and `.inspector` bind to the derived
  visibility and write intent; the width is reported to the seam, never
  used to mutate intent; the inspector toggle is disabled by `inspectorFits`
  with a help text that says to widen the window; the toolbar draws no title
  on macOS 26+ (`.toolbar(removing: .title)`) and is declared on the detail
  column — on the split view the trailing group moved to the leading edge
  once the title was gone, and a flexible `ToolbarSpacer` in either
  placement did not move it back (two captures); the window's title is the
  dataset's name.
- `mac4DSTEMApp`: Show/Hide Tools and Show/Hide Inspector label by what is
  on screen and are enabled by the same `fits`.
- `WorkspaceView`: `ResizePointer(axis:)` replaces `ColumnResizePointer`;
  the infobar shows the row-resize pointer; the canvas stays in the
  hierarchy at fraction 1 (`MetalImageView` declines to draw without a
  drawable). **Found on the way:** both drag gestures measured their
  translation in `.local` space, and the bar moves with the drag, so a
  full-height pull reached 0.51 of the column twice (709 pt over 2 × 692);
  `.global` fixes the infobar and the pane divider alike, and the third
  capture set shows fraction 1 reached and the panes back after the return
  drag.
- `WorkspaceInspector`: a segmented `Picker` in its own row + `switch`,
  `LayoutPolicy.inspectorHeaderHorizontalPadding` / `…VerticalPadding`.
- `NavigationSeamTests`: three tests, each red under one mutation (§7).

## 6. Capturing the app without a dialog — the recipe

- Build to a scratch derived-data path, never `~/Library/Developer/Xcode/DerivedData`
  (the owner's app runs from there); `open -n <app> --args --demo-fixture`.
- Window id from `CGWindowListCopyWindowInfo` (a 12-line `swift` script;
  take the window wider than 600 — the app also owns eight 2560×30 helper
  windows); `screencapture -x -l <id> out.png`.
- Resize and read control state through accessibility:
  `osascript -e 'tell application "System Events" to tell process "mac4DSTEM" to set size of window 1 to {1100, 750}'`,
  `enabled of every button of toolbar 1 of window 1`. Accessibility for the
  Claude app is already granted; no dialog.
- **System Events resolves ONE process per bundle.** An orphaned instance
  steals every call — on 2026-09-22 an instance from 01:28, running a
  binary rebuilt under it at 09:13, owned the menu bar and no window, so
  "click menu item" and "window 1" both went to it. `pgrep -fl mac4DSTEM`
  first; terminate orphans.
- Menu items via AppleScript need the window to be key (`@FocusedValue` is
  nil otherwise); drive the toolbar and infobar controls, or post CGEvents
  for drags (`tools/ui-drive/drag.swift` and the memory note).
- Read the gate's exit from a line the command wrote into its own log —
  `xcodebuild … > log 2>&1; echo "BUILD_EXIT=$?" >> log` — never from a
  wrapper: this session's first build reported "exit 0" through a
  trailing `tail` while the log said `BUILD FAILED`.
