## D025 — the real-space circle mask was half a pixel off the drawn ROI

- **Diagnosis.** `DetectorShape.realSpaceRegion` (`Core/Analysis/VirtualDetector.swift`) passed the centre as
  `Float(scanX) + 0.5`; `fillRadial` tests `Float(x) − cx`, i.e. names a pixel by its integer index — so the disc sat on
  the pixel corner. The ring is drawn at `(selectedScan + 0.5)·scale` with a floor pointer map, i.e. on the pixel centre.
  Commit `a7945be` (review item A4) made the strain mask adopt the region's `+ 0.5`, spreading it rather than removing it.
- **Measured** (64² grid, R at (30, 30)): R 5 → 88 px, centroid (30.5, 30.5) before; 97 px, (30, 30) after. 15 of ~95
  pixels change at the default radius; the centroid moves 0.71 px diagonally.
- **py4DSTEM** (`virtualimage.py`, np.indices mask): centred on the integer index. The `+ 0.5` on the radius stays
  (inclusive edge, like the rectangle's ±r) — a DEVIATION from py4DSTEM's strict `< R`, noted inline.
- **Moves:** the region-summed CBED (and the live detection preview built from it) and the selected-region strain
  reference, when the region shape is Circle. ACOM regions force Rectangle.

## D023 — empty positions exploded the strain clustering median

- **Diagnosis.** `StrainMapping.estimateLatticeBasis`: `nearest` starts at `Float.greatestFiniteMagnitude`, and
  `if nearest.isFinite` is always true, so every position with no peak beyond `minRadius` (empty or central-beam only)
  appended 3.4e38. From half the scan the median was 1.7e38, 3.4e38 or ∞; the cluster tolerance exploded, every vector
  merged, and no basis was found.
- **Measured** (400 positions, g1 (20, 0), g2 (3, 18)): 199 empty → basis found; 200–380 empty → nil before, basis after;
  below half the scan the fix moves the tolerance by ≤ 1.5 %.
- **py4DSTEM** (`process/strain/strain.py`): maxima of the whole-scan vector histogram; empty positions contribute nothing.
- **Moves:** strain on scans with ≥ 50 % empty or central-only positions (vacuum- or amorphous-heavy) goes from "no basis"
  to a map. Separate, not fixed: `occupiedPositions` counts central-only positions, raising the minimum cluster support.

## D019 — one non-finite pixel lost a pattern's peaks

- **Diagnosis.** Every detection path (live, `detectAll`, tiled) runs `DiskDetector.crossCorrelate`
  (`Core/Analysis/DiskDetection.swift`): the forward FFT spreads a NaN to every bin, `vDSP_vthres(…, 0)` maps the NaN map
  to all zeros, and `findMaxima`'s strict `>` finds nothing — diagnostics identical to vacuum. No reader sanitises
  (`H5Reader` reads `H5T_NATIVE_FLOAT`); `ProbeKernel` zeroes non-finite pixels in the kernel only. +Inf does the same.
- **Measured** (64², four disks, one NaN at (5, 5)): 0 peaks before; after the fill, the same peaks as the clean pattern.
- **py4DSTEM** loses the pattern the same way — the fix carries a DEVIATION note. Only float data can hold NaN (HDF5/EMD
  float, EMPAD, DM4 float32, dead-pixel masks, gain division); integer counting data cannot.
- **Moves:** peaks on patterns that contain a non-finite pixel; byte-identical on finite data.
