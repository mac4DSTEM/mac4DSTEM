## D006 — a multi-`data_` CIF merged into one crystal
Diagnosis: `CIFImport.parse` kept the first block name but never reset cell values, atom rows or symmetry ops at a later
`data_`: tags last-wins, loops concatenated. Refuting observation: a two-block Au+Si CIF imported without a throw (it did).
Fix: count blocks that define a structure (`_cell_length_a` or an `_atom_site_fract_x` loop; a journal-only `data_global`
is not counted) and refuse more than one by name. Prediction held: single-block files import unchanged.
Residual (refuter): a second block with only a symmetry loop still merges its operations.

## D021 — parallax stack mean stalled at 2^24
Diagnosis: `stack.reduce(0, +)` inferred `Float`; past 16 777 216 adding 1.0 rounds to nothing, so 26 M ones read as mean
0.645. Refuting observation: the Float reduce over 26 M ones returned 16 777 216 (it did). Fix: accumulate in Double.
py4DSTEM (`parallax.py:806`, numpy float32 pairwise mean) agrees with Double to < 2e-7; small stacks move by Float rounding
only (~1e-7..6e-5 relative), toward numpy. Inline DEVIATION note.

## D079 — ptychography took the aperture centre, not the fitted origin
Code reading: a drag through `AppState.updateAperture` displaces the fit, so after a drag the aperture IS the origin — the
register's drag symptom does not reproduce, by design. The real divergence: replay and lineage restore assign the aperture
directly while the calibration keeps its fitted maps; then DPC/strain/ACOM used the fitted mean and ptychography the
aperture. Fix: `ParallaxPhysicalCalibration.diffractionOrigin` = `Calibration.referenceOrigin`. Only single-slice
ptychography reads `originQX/QY`. A pre-fix replay record whose aperture differs from the fitted mean now reproduces a
different ptychography result (intended). DEVIATION: py4DSTEM shifts each pattern by its own `com_fitted`; the app by
the one mean. Unverified on real data (needs the larger Mac).
